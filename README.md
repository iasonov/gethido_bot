# gethido_bot

Инструменты для команд образовательных программ. В Telegram можно разослать одно сообщение в чаты выбранных программ. Из выгрузки студенческой оценки преподавания (СОП) можно подготовить письма о рисках для команд программ и собрать тезисы о сильных сторонах для консультаций.

## Входные и выходные файлы

| Сценарий | Что подготовить | Какие файлы появятся |
| --- | --- | --- |
| Рассылка в Telegram | `programs_real.csv` в корне репозитория, с разделителем `;`. Имя фиксированное. Само сообщение отправьте боту в Telegram. | `logs.txt` с результатами рассылок, `user_states.json` с черновиками и `user_states.json.bak` с их резервной копией. Все три файла находятся в корне репозитория. |
| Анализ рисков и предпросмотр писем (`preview`) | Выгрузка `.xlsx` через `--sop-xlsx` и справочник `.csv` с разделителем `,` через `--contacts-csv`. В примерах это `sop.xlsx` и `program_contacts.csv`. | `sop_analysis.json`, `program_summaries.csv`, `discipline_summaries.csv`, `row_issues.csv`, `email_recipients.csv`, а также письма `emails/001_Название_программы.eml` и вложения `pdfs/Название_программы_Период.pdf`. |
| Отправка писем (`send`, включая пробный режим) | Те же два файла, что для `preview`. | Те же файлы, что у `preview`, плюс журнал `send_log.jsonl` с записью на каждое обработанное письмо. |
| Проверка почты (`smtp-test`) | Адрес получателя через `--recipient` и настройки почтового сервера. | Результат — тестовое письмо на указанный адрес. |
| Сильные стороны для консультаций (`strengths`) | Выгрузка `.xlsx` через `--sop-xlsx` и подпись периода через `--module-label`. | `consultation_briefs.csv`, `score_evidence.csv`, `positive_comments.csv`, `sop_strengths.json` и карточки `programs/001_Название_программы.txt`. |

Для команд СОП имена входных файлов можно выбрать самим. Укажите фактические пути в параметрах команды. Папку результатов задаёт `--out-dir`. Для `preview` и `strengths` этот параметр обязателен, а `send` по умолчанию пишет в `output/sop_send`. В именах писем и карточек `001` — порядковый номер. Пробелы и знаки препинания в названиях программ и периодов заменяются подчёркиваниями.

## 1. Рассылка в чаты программ через Telegram

1. Откройте личный чат с ботом. Отправьте сообщение для рассылки или введите `/start` и нажмите «Отправить рассылку».
2. Выберите, кому отправить сообщение. Доступны фильтры по уровню обучения, партнёрскому статусу, кампусу и участию в раннем приглашении. На каждом шаге можно оставить все варианты.
3. Проверьте список программ. Бот сразу отмечает все программы, прошедшие фильтры. Нажмите на название программы, чтобы исключить её из рассылки или вернуть в список. Если список пуст, измените фильтры.
4. Проверьте текст и список программ на экране подтверждения. Кнопка «Подтвердить и начать рассылку» запускает отправку. До подтверждения можно вернуться к выбору программ или отменить подготовку командой `/cancel`.

Бот копирует исходное сообщение в чаты по очереди. При тайм-ауте он делает до трёх попыток на чат. По ходу отправки бот показывает результат по каждой программе. В конце все администраторы получают сводку с именем отправителя, текстом и числом успешных отправок. Подробный результат сохраняется в `logs.txt`, а черновик до отправки — в `user_states.json` с резервной копией `user_states.json.bak`.

**Кто может отправлять.** Только пользователи, чьи Telegram ID указаны в `ADMIN_IDS` в [gethido_bot.py](gethido_bot.py).

**Откуда берутся чаты.** Бот читает [programs_real.csv](programs_real.csv). Для выбора адресатов используются название программы (`program`), уровень (`level`), партнёр (`partner`), кампус (`campus`), участие в раннем приглашении (`early_invitation`) и ID чата (`tg_chat_id`). В список попадают строки с числовым ненулевым ID чата. Для отправки у бота должно быть право писать в этот чат.

### Как узнать Telegram ID сотрудника или группы

- **ID сотрудника.** Откройте [@userinfobot](https://t.me/userinfobot), нажмите «Старт» и перешлите боту тестовое сообщение от сотрудника. Скопируйте число из поля `Id` в ответе с именем сотрудника и добавьте его в `ADMIN_IDS` в `gethido_bot.py`. Если настройки приватности скрывают автора при пересылке, попросите сотрудника самому нажать «Старт» у этого бота и прислать число из ответа. [Как Telegram передаёт данные об авторе пересланного сообщения](https://core.telegram.org/bots/api#messageorigin)
- **ID группы через Telegram Web.** Откройте нужную группу в [Telegram Web A](https://web.telegram.org/a/). Если адрес выглядит как `https://web.telegram.org/a/#-1001234567890`, скопируйте `-1001234567890` в столбец `tg_chat_id` в `programs_real.csv`. Сохраните знак минус. Если в конце адреса есть `_42` или другой суффикс после подчёркивания, берите только число до подчёркивания. [Как Telegram Web A формирует адрес чата](https://github.com/Ajaxy/telegram-tt/blob/master/src/util/routing.ts#L95-L120)
- **ID группы через бота.** Если в адресе нет числового ID, временно добавьте [@GetIDsBot](https://t.me/GetIDsBot) в группу и скопируйте `id` из блока `This chat` в его приветственном сообщении. При пересылке обычного сообщения участника Telegram передаёт данные об авторе, когда это разрешено настройками приватности. Данные о чате могут быть доступны, если исходное сообщение отправлено от имени группы или опубликовано в канале. [Как GetIDsBot определяет ID группы](https://github.com/wjclub/telegram-bot-getids/blob/master/src/index.ts#L282-L306), [данные о пересланных сообщениях](https://core.telegram.org/bots/api#messageorigin)

## 2. Поиск рисков по результатам СОП

Анализ показывает, по каким дисциплинам и показателям команда программы может разобрать низкие оценки. На вход нужна выгрузка СОП в формате `.xlsx` с четырьмя листами.

- `Преподаватели на ОП`
- `Дисциплины(ЭПП) на ОП`
- `МООК на ОП`
- `Доп.инф. по ЭПП`

На каждом листе нужны столбцы «Программа» и «Дисциплина». Если в выгрузке указан уровень обучения, он добавляется к названию программы, чтобы различать одноимённые программы. Для расчёта используются числовые показатели по шкале от 1 до 5. Показатели сложности, комментарии и служебные столбцы исключаются.

| Что проверяется | Требует внимания | Есть риски |
| --- | --- | --- |
| Строка выгрузки | Хотя бы одна оценка ниже 3 или хотя бы две оценки ниже 4 | Ровно одна оценка от 3 включительно до 4 |
| Дисциплина на конкретном курсе | Хотя бы одна её строка требует внимания | Есть хотя бы одна строка с риском, а строк со статусом «Требует внимания» нет |
| Программа | Хотя бы одна дисциплина требует внимания или две и более дисциплины имеют риски | Ровно одна дисциплина имеет риски, а дисциплин со статусом «Требует внимания» нет |

Строки с оценками от 4 и выше по всем заполненным показателям имеют статус «Без риска». В итоговые таблицы и почтовую рассылку попадают только выявленные риски.

Анализ выполняется в командах `preview` и `send`. В папке результатов появляются `program_summaries.csv` со статусами программ, `discipline_summaries.csv` со статусами дисциплин по курсам, `row_issues.csv` с низкими оценками и `sop_analysis.json` с полным результатом анализа.

## 3. Подготовка и отправка писем о рисках

Для каждой программы с рисками формируется одно письмо. В нём перечислены дисциплины по статусам и их минимальные оценки. В приложенном PDF указаны курс, дисциплина, преподаватель или другой объект оценки и показатели с низкими баллами.

**Кому приходят письма.** В поле «Кому» указываются академические руководители. В копию добавляются менеджеры программы, дополнительные получатели из справочника и постоянные получатели из [email_notifications.py](email_notifications.py).

**Как обновить адресатов.** Используйте [program_contacts.csv](program_contacts.csv) как справочник контактов. В `program` укажите название программы, в `academic_lead_emails` — адреса академических руководителей. Столбцы `manager_emails`, `extra_cc_emails` и `program_aliases` должны быть в файле, их значения могут быть пустыми. Если название в СОП отличается, укажите его в `program_aliases` с уровнем в формате `Название / Магистратура` или `Название / Бакалавриат`, когда уровень есть в выгрузке. Несколько вариантов названия разделяются знаком `|`, несколько адресов в одном поле — точкой с запятой. Подготовка останавливается при неверном формате адреса, конфликте названий или отсутствии контактов для программы с рисками.

### Проверка перед отправкой

Команда `preview` сохраняет письма в `emails/` в формате `.eml`, вложения в `pdfs/` и сводку адресатов в `email_recipients.csv`. По ним можно проверить период, текст, получателей и вложения. Для предпросмотра достаточно выгрузки СОП и справочника контактов. В `--module-label` подставьте период своей выгрузки.

```powershell
python -m sop_cli preview --sop-xlsx sop.xlsx --contacts-csv program_contacts.csv --out-dir output/sop_preview --module-label "3 модуль 2025/2026"
```

### Отправка

Команда `send` заново анализирует выгрузку и собирает письма. Используйте те же входные файлы и период, которые проверили на предпросмотре. Режим `--dry-run true` использует настроенного отправителя и сохраняет файлы и журнал без отправки. Режим `--dry-run false` отправляет письма.

```powershell
python -m sop_cli send --sop-xlsx sop.xlsx --contacts-csv program_contacts.csv --out-dir output/sop_send --module-label "3 модуль 2025/2026" --dry-run false
```

В `send_log.jsonl` добавляется запись на каждое подготовленное в пробном режиме или успешно отправленное письмо. Если почтовый сервер возвращает ошибку после повторных попыток, отправка останавливается. Перед повторным запуском проверьте журнал. Команда заново обрабатывает весь список, поэтому уже отправленные письма могут уйти повторно.

Чтобы проверить почтовые настройки, отправьте одно тестовое письмо на свой адрес через `smtp-test`. Замените адрес в примере на свой.

```powershell
python -m sop_cli smtp-test --recipient you@example.org
```

## 4. Сильные стороны программ для консультаций

Команда `strengths` использует ту же выгрузку СОП и готовит карточки по всем программам из неё, включая программы без рисков. В карточку могут попасть, например, ясность требований, качество преподавания или организация практики.

Для каждого показателя на каждом листе сначала усредняются оценки внутри каждой пары «курс и дисциплина». Затем берётся среднее этих результатов с одинаковым весом для каждой пары. По программе выбираются до трёх разных сильных сторон со средним баллом от 4 из 5. Тезисы относятся к оценённым дисциплинам за указанный период. Если подходящих оценок нет, в карточке появляется примечание для менеджера. Позитивные комментарии студентов выгружаются отдельно для ручного разбора, а готовые тезисы строятся по числовым оценкам.

```powershell
python -m sop_cli strengths --sop-xlsx sop.xlsx --out-dir output/sop_strengths --module-label "3 модуль 2025/2026"
```

- `consultation_briefs.csv` — тезисы по программам, оценки, названия листов и номера строк исходной выгрузки.
- `programs/` — отдельные текстовые карточки программ с тезисами, основаниями и позитивными комментариями.
- `score_evidence.csv` и `positive_comments.csv` — исходные оценки и комментарии с привязкой к строкам Excel.
- `sop_strengths.json` — полные результаты с методикой расчёта.

Выгрузка сохраняется локально. Для неё достаточно файла СОП и подписи периода.

## Как запустить

Выполняйте команды из корня репозитория в окружении Python 3.11 или новее. Зависимости перечислены в [pyproject.toml](pyproject.toml). Пример настройки окружения в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install "openpyxl>=3.1.2" "pandas>=2.2.0" "reportlab>=4.0.0" "requests>=2.31.0"
```

**Telegram.** Укажите `BOT_TOKEN` в локальном файле `my_secrets.py`, проверьте список `ADMIN_IDS` и справочник чатов. Запустите `python gethido_bot.py`.

**Почта.** Для `send` и `smtp-test` задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD` и `SMTP_FROM_EMAIL` в переменных окружения или в локальном `my_secrets.py`. Переменные окружения имеют приоритет. При необходимости можно задать имя отправителя через `SMTP_FROM_NAME`. Для создания PDF нужен поддерживаемый шрифт с кириллицей, например Arial в Windows или DejaVu Sans в Linux.

**Команды и тесты.** Список команд СОП доступен через `python -m sop_cli --help`. Для тестов используйте `python -m unittest discover`.
